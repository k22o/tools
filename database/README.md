# Database

データベースの基礎知識、種類ごとの特徴、および各データベースの実装サンプルをまとめる。

## 1. データベースの種類

データの格納方法やデータの扱い方によって、データベースはいくつかの種類に分類できる。

### 1.1 リレーショナルデータベース（RDB）

データをテーブル（表）形式で管理するデータベース。

- [RDB・SQL](./rdb-sql/README.md)
- [mySQLサンプル](./mysql)

以下の特徴を持つ。

- SQLを用いてデータを操作する
- テーブル間の結合（JOIN）など、複雑なデータ操作が可能
- トランザクションによるデータの一貫性を保証する
- データの整合性を制約（主キー・外部キーなど）によって管理できる

### 1.2 NoSQLデータベース

RDBとは異なるデータモデルやデータ管理方式を採用したデータベースの総称。
[NoSQL](./nosql/README.md)

- スキーマの柔軟性が高いものが多い
- 大量データや分散環境での処理に適したものがある
- データモデルによって特徴や用途が異なる

### 1.3 その他のデータベース・検索基盤

特定の用途に特化したデータ管理・検索システム。

| 種類 | 特徴 | サンプル |
|---|---| --- | 
| ベクトルデータベース | ベクトル化されたデータを格納し、類似度検索を行う | [qdrant](./qdrant/README.md) | 
| 検索エンジン型データベース | 全文検索や高速な検索・集計を得意とする | [elasticsearch](./erasticsearch/README.md) | 

※ 検索エンジン型は、一般的なRDBやNoSQLとは異なる観点での分類であり、NoSQLに分類される製品もある。

## 2. データベースのスケーラビリティによる分類

スケーラビリティ向上のさせ方によって、いかのようなパターンに分けられる。

1. 単一インスタンス
1. スケールアウト - 分散DB化 ([distributed_db.md](./distributed_db.md))
   1. レプリケーション
   1. シャーディング
1. コンポーネント分離 (クエリエンジンとストレージエンジンの分離)
1. コンポーネント分離 + スケールアウト (-> NewSQL)

**※ コンポーネント分離について**

- メリット
   - クエリとストレージ側で独立してコンピューティングリソースを調整できる
   - リード専用のクエリエンジンを簡単にスケールアウトできる (クエリエンジン単体のレプリケーション)
- デメリット 
   - 書き込みはスケールアウトできない
   - ストレージエンジン側のスケールアウトが難しい

## 3. データベースの設計・運用

### 3.1 Migration Tool

データベースのスキーマ変更やテーブル更新をコードで管理するためのツール。

主な機能：
- テーブルやカラムなどのスキーマ変更をコード化
- マイグレーションの実行履歴を管理
- 環境間でデータベースの構造を統一
- スキーマ変更の適用・ロールバック

代表的なツール：
- Flyway
- sql-migrate

※ Ruby on Railsなどのフレームワークでは、マイグレーション機能が標準で提供されている。
