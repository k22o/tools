# ファイルディスクリプタ

## ファイルディスクリプタとは

**ファイルディスクリプタ（File Descriptor / FD）**とは、プロセスが開いているファイルやソケットなどのI/Oリソースを識別するための**整数値**。
例えば、ファイルを開くとOSからFDが割り当てられる。

```text
open("sample.txt")　-> FD 3 -> sample.txt
```

FDそのものは単なる番号であり、**その番号がどのI/Oリソースを指しているかはOSが管理する**。

プログラムはFDを指定してI/Oを行う。

```text
read(3, ...)
write(3, ...)
close(3)
```

名前に「ファイル」とあるが、FDはファイル以外のI/Oリソースにも使われる(ファイル,ソケット,パイプ,デバイスなど)。
特にネットワーク通信では、**ソケットもFDとして扱われる**。
そのため、サーバーでは**同時接続数が増えるとFDの使用数も増える**。

---

## 標準入出力

プロセスには代表的なFDがあらかじめ用意されている。

| FD | 名前     | 用途      |
| -: | ------ | ------- |
|  0 | stdin  | 標準入力    |
|  1 | stdout | 標準出力    |
|  2 | stderr | 標準エラー出力 |

例えば、

```bash
echo "hello" > output.txt
```

では、`echo` の標準出力（FD 1）が `output.txt` に接続される。

---

## FDテーブル

**プロセスごとにFDを管理するためのテーブル**が存在する。

```text
プロセス
└── FDテーブル
    ├── 0 → stdin
    ├── 1 → stdout
    ├── 2 → stderr
    ├── 3 → ファイル
    └── 4 → ソケット
```

FD番号は、プロセスからI/Oリソースを参照するための**ハンドル**のようなもの。
そのため、異なるプロセスのFD `3` が同じI/Oリソースを指すとは限らない。

---


## FDとinode

* **FD**：プロセスからI/Oリソースを参照するための番号
* **inode**：ファイルの属性やデータへの情報を管理するもの

したがって、**FD = ファイルそのもの**ではない。

---

## FDのライフサイクル

```text
open()
  ↓
FD取得
  ↓
read / write
  ↓
close()
  ↓
FD解放
```

---

## FDの枯渇

プロセスが利用できるFD数には上限がある。
ファイルやソケットを大量に開いたり、不要なFDを閉じ忘れたりすると、利用可能なFDがなくなる。
これを**FDの枯渇（FD exhaustion）**という。
"Too many open files"

主な原因としては...

* ファイルを `close()` し忘れる
* ソケットを閉じ忘れる
* 接続が大量に発生する
* 接続プールなどが大量の接続を保持する
* FDの上限値が低い

特にサーバーでは、**FDリーク**（不要になったFDを解放しないこと）が長時間稼働後の障害原因になる。

---

## I/O多重化

多数のFDを効率的に監視する仕組みとして、I/O多重化がある。

代表的なもの：

* `select`
* `poll`
* `epoll`

特にLinuxのサーバーでは `epoll` が利用される。

```text
多数のSocket
     ↓
多数のFD
     ↓
   epoll
     ↓
I/O可能なFDを検出
```

これにより、多数のネットワーク接続を効率的に処理できる。
